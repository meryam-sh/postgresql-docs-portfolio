# Contributing to This Documentation Portfolio

This is a learning repository. Suggestions and corrections are welcome.

## Style guide

- Use clear, task-oriented titles.
- State the audience, prerequisites, and supported environment.
- Present procedures as numbered steps with expected results.
- Put SQL and shell commands in labeled code blocks.
- Explain warnings before commands that can change or remove data.
- Link to official documentation for technical claims.
- Mark untested examples as illustrative; do not claim validation without evidence.

## Proposed review process

1. Create a branch for the change.
2. Make one focused documentation improvement.
3. Open a pull request summarizing what changed and how it was tested.
4. Request a technical review when commands or database behavior are involved.
5. Merge after review and automated checks.

This file describes the intended workflow; it does not imply that every sample has already been independently reviewed.
